# specify

A card in specify/done/ is a story whose specifications the Product Owner has
accepted.

## Do
Run the `specify` skill on the story file the card's `refine.artifacts` names,
with the person. It writes the story's `spec.md` index and one file per use case
or query.

## Record
- `attempt`
- `artifacts`: `spec.md` and every specification file it indexes, and every ADR
  it drafted with the ADR log
- `summary`: the use cases and queries, one line each
- `open_questions`: anything specify could not settle with the person

## Gate
Ask the Product Owner once: must anything outside the team be in place first,
or is anything assumed that nobody confirmed, that is not yet on record? Write
each new one into the owning file's `## Open questions`, index it in `spec.md`'s
`## Dependencies`, and go on.

Show the Product Owner the index, every specification whole, its `sources`
included, each glossary term marked `(assumed)`, and every `Proposed` ADR it
drafted. Their word is the verdict; record it. On an approve,
remove `(assumed)` from each term shown. The glossary is shared by every card, so it
does not wait for the merge: then commit it alone in the main tree,
`git commit -m "docs(<card id>): glossary" -- GLOSSARY.md`, when it changed.
Mark each ADR they accept `Accepted` and remove each they reject; ADRs bind
every later change too, so commit them alone in the main tree, with the ADR log,
`git commit -m "docs(<card id>): ADR-<n>[, ADR-<m>]" -- <ADR files> <ADR log>`.
On a reject, remove the specification's `Proposed` ADRs and their log rows.
