# test

A card in test/done/ has a change an independent verification ran, exercised
and mutation-probed against its specifications, and found to do what they say.

## Record
The verification's report, as it gives it:
- `attempt`
- `artifacts`: `[]` — a verification writes nothing
- `summary`: the verdict, and one line per mismatch
- `verdict`, `revision`, `evidence`, `mismatches`
- `follow_ups`: opened as build's `## Record` opens them

## Gate
Run the `test` skill inside the card's worktree, `build.worktree`, never in the
main tree, on the change the card's `build.commits` make, against the
`spec.md` and every specification file the card's `specify.artifacts` names,
with the plans under `plans/` in `design.artifacts` as the cases design decided.
The implementer's claims are `build.cases`, `build.acceptance_tests`,
`build.superseded`, `build.departures`, `build.follow_ups`, `build.answers`,
`build.test_command` and `build.test_result`; the bookkeeping path is `.kanban/`. You have no transcript
of the build, and want none.
Other work may share this machine: end only a process you started, by its PID,
never by name (`pkill -f`, `killall`); a hung test run is run once more, not
killed by name.

A card that already carries a `test` block came back through build: that block
is the earlier verification — its `revision`, `evidence` and `mismatches` — and
the rework is every `build.commits` entry its `revision` does not contain. When
its `evidence` does not end with its restore proof, it carries nothing, and
every mutant runs again.

A card maintain returned to test after its base check holds the base branch
merged into the worktree, uncommitted. Verify the worktree as it stands: that
merged tree is what the verdict covers. Its `HEAD` is the card's last commit,
so no `build.commits` entry is new; the rework is every file the merge changed
against the earlier `revision`, and the carry rule runs those again.

`pass` is approved. `fail` is rejected, and the card goes back to build.
