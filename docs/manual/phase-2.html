2自動蒸餾：讓 AI 自己整理

在 Phase 1，你要主動喊「蒸餾」館員才會整理。開啟自動蒸餾後，每次對話結束、且這次有成功歸檔到新素材時，系統會在背景自動跑一次 /digest——你什麼都不用做。

怎麼開啟

設一個環境變數 PALACE_AUTO_DIGEST=1 就開了。關鍵是把它設在「啟動 Claude 的那個環境」裡，分兩種情況：

情況 A · 從終端機啟動 Claude Code

把這行加進你的 shell profile（zsh 是 ~/.zshrc，bash 是 ~/.bashrc），然後開一個新的終端機視窗讓它生效：

# ~/.zshrc　（或 ~/.bashrc）export PALACE_AUTO_DIGEST=1

情況 B · 從 Dock／Finder 啟動的 GUI app（macOS）

從圖示點開的 app 讀不到你在終端機 export 的變數（這是最常見的坑，見第 6 節）。在 macOS 讓 GUI app 也看得到，用 launchctl，設完重啟該 app：

launchctl setenv PALACE_AUTO_DIGEST 1

launchctl setenv 設的值重開機後會消失。想永久保留，把它做成登入時執行的 LaunchAgent；或單純每次需要時再設一次。

成本提醒（請先讀）

自動蒸餾每次對話結束都會在背景呼叫一次 Claude（headless 執行 /digest），這會實際消耗你的 API 額度或訂閱用量。對話越頻繁、花費越多。這也是為什麼預設是關閉的——請你確認願意付這個成本，再顯式開啟。

它不會亂跑

只有在「這次對話真的有歸檔到新素材」時才觸發（沒有新東西就不值得花 token）；而且同一時間只會有一個蒸餾在跑，靠一個 lock 檔防止重複啟動。

去哪看它有沒有跑

背景蒸餾的所有輸出都會寫進這個記錄檔。想確認有沒有跑、跑得順不順，看它就對了：

tail -f .palace-state/autodigest.log

看到蒸餾的執行過程與結果，代表它有在動；檔案一直沒長大，代表沒被觸發（可能沒開、或這次沒有新素材）。

怎麼關閉

把剛才設的變數拿掉即可：從 ~/.zshrc 刪掉那行（或改成 PALACE_AUTO_DIGEST=0）後開新終端機；GUI app 則執行 launchctl unsetenv PALACE_AUTO_DIGEST 再重啟 app。關掉後，隨時還能手動喊「蒸餾」或打 /digest。

3把記憶接到其他 AI 產品

你的書庫附了一個 MCP 記憶伺服器（名為 palace-memory）。任何支援 MCP 的 AI 工具掛上它，就能讀你這座書庫——喚醒開場記憶、搜尋、精讀。它只讀不寫，安全無虞。

一個關鍵設定：PALACE_VAULT

伺服器預設去「當前工作目錄下的 vault/」找書庫。但別的 app 啟動時的工作目錄通常不是你的專案資料夾，所以要用環境變數 PALACE_VAULT 明確指到你 vault 的絕對路徑。下面每個範例都會帶上它。

接到 Claude Desktop

  1. 打開 MCP 設定
    Claude Desktop → Settings（設定）→ Developer / MCP，編輯它的設定檔 claude_desktop_config.json。
  2. 在 mcpServers 裡加一個 palace-memory 條目
    路徑都用絕對路徑（把 /Users/你/llm-wiki 換成你自己的專案路徑）：
    // claude_desktop_config.json{ "mcpServers": { "palace-memory": { "command": "bun", "args": ["/Users/你/llm-wiki/tools/mcp/server.ts"], "env": { "PALACE_VAULT": "/Users/你/llm-wiki/vault" } } } }
  3. 重啟 Claude Desktop，實測
    重開後，對它說「喚醒你的記憶」或「幫我搜尋書庫裡關於 ○○ 的紀錄」。它應會用 memory_wake / memory_search 讀到你的內容。

接到其他專案的 Claude Code

兩種做法，擇一：

做法怎麼做
放進專案的 .mcp.json 在另一個專案根目錄的 .mcp.json 加上同樣的 palace-memory 條目（args 用絕對路徑、env.PALACE_VAULT 指到你的 vault）。該專案的 Claude Code 就會自動載入。
臨時用 --mcp-config 把設定存成一個檔（如 palace.mcp.json），啟動時帶上 claude --mcp-config /路徑/palace.mcp.json。不想改動專案檔時很方便。
本專案內不用設

在 llm-wiki 這個專案裡，.mcp.json 已經註冊好 palace-memory，工作目錄就是專案根，vault/ 找得到，不必再設 PALACE_VAULT。上面這些設定是給別的 app／專案用的。

接到其他相容 MCP 的工具（通用說明）

任何吃「stdio MCP 伺服器」的工具都能掛。通用參數是同一組三件：

欄位值說明
啟動指令bun需要系統裝了 Bun，且該工具找得到 bun（PATH 上，或填 bun 的絕對路徑）。
參數/絕對路徑/tools/mcp/server.ts指向本專案的 MCP 伺服器檔。
環境變數PALACE_VAULT=/絕對路徑/vault指到你的 vault。省略的話伺服器只會找「該工具工作目錄下的 vault」，多半找不到。

4四個記憶工具，AI 何時用哪個

掛上 palace-memory 後，AI 手上多了四個工具。你不用直接操作它們——AI 會依對話需要自己挑。認得它們，能幫你看懂 AI 正在做什麼。

開場 · 想起你是誰

memory_wake

對話一開始就用。回傳「喚醒包」——你的身分（identity）＋現在最重要的事（essential-story）。讓 AI 開口前先想起你是誰、正在忙什麼。

找記憶 · 關鍵字搜尋

memory_search

當 AI 需要確認「這件事之前談過嗎」。對整座書庫的筆記逐行搜尋關鍵字，回傳命中的「檔案:行號:片段」，快速定位相關頁面。

精讀 · 讀整篇

memory_read

搜尋定位到某一頁後，用它把整篇讀進來看細節。是「找到了 → 打開來仔細看」的那一步。

導覽 · 瀏覽目錄

memory_list

列出書庫某一層的目錄與檔案，像逛書架。當 AI 想先摸清結構、或不確定該往哪找時用來導覽。

典型的一次記憶取用

開場 memory_wake 想起你 → 遇到具體問題 memory_search 找出相關頁 → memory_read 讀該頁細節（必要時 memory_list 先看看附近還有什麼）。四個工具合起來，就是 AI 在別的產品裡「翻你這座書庫」的方式。

5索引自動更新

書庫每個資料夾都有一份 index.md 目錄。Phase 2 起，它會自己保持最新。

會自動發生的事

每次對話結束、且成功歸檔後，系統會就地重生所有 index.md（純文字重算，很快，不呼叫 AI、不花額度）。所以你新增、蒸餾出來的頁面，目錄會立刻對得上，不再有「條目在、目錄漏列」的落差。

手動指令仍然可用

想立刻重生（例如剛手動改了某頁的一句話描述），照 Phase 1 一樣打：

bun run reindex
別手改 index.md

index.md 是自動生成的，手改會在下次重生時被蓋掉。要調整顯示內容，改各知識頁自己的 title / description；要調整導覽路線，改 palace/map.md。

6疑難排解

自動蒸餾好像卡住了 / lock 卡住

蒸餾靠 .palace-state/digest.lock 這個檔防止重複啟動，裡面存的是持有者的程序編號（PID）。系統會自癒：下次要蒸餾時若發現持有者早就結束了，會自動把過期的 lock 清掉再重跑，通常你什麼都不用做。

若真的想手動強制解鎖，直接刪掉這個檔即可：

rm .palace-state/digest.lock

MCP 連不上 / 別的 app 看不到記憶

三個地方最常出錯，逐一檢查：

  • bun 路徑：那個 app 不一定找得到 bun。用終端機跑 which bun 查出絕對路徑，把設定裡的 "command": "bun" 換成該絕對路徑。
  • 工作目錄（cwd）／PALACE_VAULT：伺服器預設找「cwd 下的 vault」，但別的 app 的 cwd 多半不是你的專案。務必用 PALACE_VAULT 指到 vault 的絕對路徑。
  • 路徑寫對了嗎：args 裡 tools/mcp/server.ts 與 PALACE_VAULT 都用絕對路徑，別留相對路徑。改完重啟那個 app。

開了自動蒸餾，卻沒反應

最常見的坑：環境變數沒傳進 GUI app。你在終端機 export PALACE_AUTO_DIGEST=1，只對「從那個終端機啟動的程式」有效；從 Dock／Finder 點開的 app 看不到。解法見第 2 節情況 B：用 launchctl setenv 設定後重啟 app。

其他要確認的：

  • 這次對話有沒有歸檔到新素材——沒有新東西就不會觸發。
  • claude 指令是否在 PATH 上——背景蒸餾要靠它啟動。
  • 看 .palace-state/autodigest.log 有沒有輸出；完全沒動，代表根本沒被觸發（多半是變數沒吃到）。
