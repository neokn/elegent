1這是什麼

把這套系統想像成一座圖書館，裡面有兩種訪客。

給人

📖 閱覽室：PARA

你走進來看整理好的成果。四個資料夾按「你現在能對它做什麼」分類：projects（進行中的專案）、areas（長期責任）、resources（知識主題）、archives（已完結）。

給 AI

🗄️ 書庫：palace 記憶宮殿

人平常不進去，但館員（你的 AI 助理）靠它跨對話記得事情。裡面存放逐字紀錄、事實表、索引——是 AI 的長期記憶基礎設施。

它解決什麼問題？

一般的 AI 每開一次新對話都「從零開始」，像每次都要重新翻一整櫃資料才能回答你，講過的事轉頭就忘——知識不會累積。

這套系統換個做法：AI 把學到的東西寫進一份持久的 wiki，一次寫好、持續維護、越用越聰明。就像把零散便條整理成一本會長大的百科——知識會複利累積。

兩層保存，各司其職

逐字層像錄音存證：對話一字不改地留底，只增不減。蒸餾層是館員讀完存證後、寫成的整潔條目。存證永遠在，所以整理錯了隨時能重來。

整套系統，一顆工具

這套系統以一顆名為 elgt 的執行檔交付（EleGent 的縮寫——大象永不忘記，正好用來管記憶）——程式、範本、連同執行環境全部壓在單一檔案裡，像一支瑞士刀：所有刀刃收在同一個握把，放進口袋（PATH）就走到哪用到哪。這顆檔案約 57 MB，看起來不小，是因為它把「執行環境」也一起打包了，所以你的電腦上什麼都不用先裝。

📦

一顆執行檔

程式、範本、執行環境全包在單一檔案裡。不必安裝任何開發工具，下載即用。

🏗️

空資料夾一鍵成形

elgt init 能在任何空資料夾裡，一次長出一座完整、可用的記憶書庫。

🔌

記憶跟著你到每個 AI

透過 MCP，同一座書庫可以接到 Claude Desktop、Codex、Gemini……多個 AI 共用一份記憶。

2安裝 elgt

三種方式，任選一種。裝完都用同一句話驗證：elgt version 印出版本號就成功了。

先確認：平台與發佈狀態

目前提供的現成執行檔只支援 macOS（Apple 晶片，arm64）。另外，方式 A／B 都是去 GitHub 的 Releases 抓檔，所以前提是 neokn/EleGent 這個專案已經發佈過一版 release（且附了 elgt-darwin-arm64 這個檔）。若還沒有 release，或你的電腦不是 macOS arm64——請走方式 C：自己編一顆。

方式 A · 一行安裝（最省事，建議）

打開「終端機」，把下面這行貼上去按 Enter。它會自動下載最新版、放到 ~/.local/bin/elgt、順手處理好 macOS 的安全性攔阻：

curl -fsSL https://raw.githubusercontent.com/neokn/EleGent/main/install.sh | bash

裝完你會看到「已安裝 …/elgt」。如果它提醒你 ~/.local/bin 不在 PATH（系統找不到指令的清單）裡，照它印出的那行 export PATH=... 加進你的設定檔、重開一個終端機視窗即可（詳見第 10 章）。

方式 B · 手動下載（不想用 curl 管線時）

  1. 到 Releases 頁抓檔
    打開 github.com/neokn/EleGent/releases，在最新一版下載名為 elgt-darwin-arm64 的檔案。或直接用這個「永遠指向最新版」的網址：
    https://github.com/neokn/EleGent/releases/latest/download/elgt-darwin-arm64
  2. 改名、給執行權限、放進 PATH
    把它改名成 elgt、標記為可執行，放到系統找得到的地方（例：~/.local/bin）：
    mkdir -p ~/.local/bin mv ~/Downloads/elgt-darwin-arm64 ~/.local/bin/elgt chmod +x ~/.local/bin/elgt
  3. 解除 macOS 的下載攔阻
    從瀏覽器下載的執行檔，macOS 會先攔下來。手動移除這個標記（方式 A 的安裝腳本已自動做了這步）：
    xattr -d com.apple.quarantine ~/.local/bin/elgt

方式 C · 自己編一顆（沒有 release，或非 macOS-arm64）

這條路需要 Bun（開發環境），適合「還沒發佈 release」或「想自己掌握版本」的情況。在專案原始碼資料夾裡：

bun install bun run build

完成後會在 dist/elgt 產出一顆執行檔（約 57 MB）。把它複製或連結到你 PATH 上的資料夾即可，例如：

cp dist/elgt ~/.local/bin/elgt
關於平台

目前 bun run build 只鎖定 macOS arm64 這個目標。其他平台（Intel Mac、Linux、Windows）暫時沒有現成執行檔——在那些系統上，請改用開發模式（裝 Bun、抓原始碼、用 bun run ... 指令），功能完全一樣，對照表見速查。

驗證安裝

不管用哪種方式，開一個新的終端機視窗，打：

elgt version0.3.0

看到版本號（如 0.3.0）印出來，就代表 elgt 已就位、系統找得到它。若出現「command not found」，是 PATH 沒設好，見第 10 章。

3快速開始：三句指令建一座記憶

裝好 elgt 後，在任何空資料夾裡跑一次 elgt init，就能長出一座完整、當場可用的記憶書庫。第一次設定約 10 分鐘，之後日常幾乎不用碰指令。

  1. 建一個資料夾，走進去
    名字隨你取，這裡叫 my-memory。它會是你這座書庫的家。
    mkdir my-memory && cd my-memory
  2. 一鍵初始化
    這一句會在當前資料夾鋪好整套系統：一個 vault/ 書庫（含 palace/ 記憶宮殿與 PARA 分類）、自動歸檔的 hooks 設定、蒸餾技能，以及 elegent-memory MCP 設定——並自動建立 git 版本庫、存下第一個存檔點。新版本不再產生 CLAUDE.md / AGENTS.md 人設檔；行為由 skill + MCP 承載。
    elgt init
    跑完它會告訴你新增了哪些檔案，並列出「下一步」。
  3. 填自我介紹（identity）
    用任何編輯器打開這個檔，寫下「你是誰、身邊關鍵的人、你希望 AI 怎麼跟你互動」。這是唯一需要你親手寫的檔案，AI 只讀不改——它會在每次新對話開場自動想起這些內容：
    vault/palace/wake/identity.md
  4. （建議）用 Obsidian 打開 vault 資料夾
    下載免費的 Obsidian，選「Open folder as vault」，指向 my-memory/vault。就能像逛筆記一樣瀏覽、雙向連結你的記憶。這步純為了你自己看，不影響 AI 使用。
  5. 在這個資料夾裡開 Claude Code——記憶自動生效
    在 my-memory 資料夾裡啟動 Claude Code（若已開著，重啟或開一個新對話）。因為 init 已經依 scope 註冊記憶 hooks 與 elegent-memory 記憶伺服器，這裡的每個 session 都會自動掛上你的記憶——開場想起你、對話自動存底。你什麼都不用手動接。
為什麼「這個資料夾」就自動生效

init 會依你選的 scope 設定 hooks 與 MCP：預設寫到 user scope，project/local 則綁到目前資料夾；local scope 會建立 .專案名.vault/ 並加入 .gitignore。因此記憶可以是全域共享，也可以是某個專案私有——見第 8 章。

完成了嗎？

做完這五步，系統就上線了。從現在起，你在這個資料夾裡跟 AI 的每一段對話都會被自動存進書庫——你什麼都不用做。

4日常使用

兩件事：對話自動存底（你不用管）、想整理時喊一聲蒸餾。

對話自動歸檔（三個時機）

你不需要按任何「儲存」。系統會在三個時機自動把逐字紀錄存進 vault/palace/raw/conversations/<專案名>/：

時機什麼時候為什麼
平時每講約 15 則訊息，自動存一次邊聊邊備份，完全不打擾你
壓縮前對話太長、AI 要壓縮記憶之前先完整存檔避免舊內容被壓縮掉、從此消失
結束時關掉對話時再補存一次連很短的對話也不會漏掉

什麼時候跑 /digest（蒸餾）？

逐字紀錄只是「存證」，還沒整理成正式條目。當你想把累積的紀錄整理進 wiki 時，跟 AI 說「消化」「蒸餾」或直接打 /digest。館員會讀還沒整理的紀錄，寫進對應的 PARA 頁面與書庫結構，並自動存檔（git commit）。

建議節奏

一個段落的工作告一段落、或累積了幾則對話後，跑一次蒸餾即可。不必每次對話都跑——存證一直都在，慢慢消化也不會遺失。嫌麻煩的話，第 6 章教你開「自動蒸餾」，連喊都不用喊。

6自動蒸餾：讓 AI 自己整理

預設情況下，你要主動喊「蒸餾」館員才會整理。開啟自動蒸餾後，每次對話結束、且這次有成功歸檔到新素材時，系統會在背景自動跑一次 /digest——你什麼都不用做。

怎麼開啟

設一個環境變數 ELEGENT_AUTO_DIGEST=1 就開了。關鍵是把它設在「啟動 Claude 的那個環境」裡，分兩種情況：

情況 A · 從終端機啟動 Claude Code

把這行加進你的 shell profile（zsh 是 ~/.zshrc，bash 是 ~/.bashrc），然後開一個新的終端機視窗讓它生效：

# ~/.zshrc　（或 ~/.bashrc）export ELEGENT_AUTO_DIGEST=1

情況 B · 從 Dock／Finder 啟動的 GUI app（macOS）

從圖示點開的 app 讀不到你在終端機 export 的變數（這是最常見的坑，見第 10 章）。在 macOS 讓 GUI app 也看得到，用 launchctl，設完重啟該 app：

launchctl setenv ELEGENT_AUTO_DIGEST 1

launchctl setenv 設的值重開機後會消失。想永久保留，把它做成登入時執行的 LaunchAgent；或單純每次需要時再設一次。

成本提醒（請先讀）

自動蒸餾每次對話結束都會在背景呼叫一次 Claude（headless 執行 /digest），這會實際消耗你的 API 額度或訂閱用量。對話越頻繁、花費越多。這也是為什麼預設是關閉的——請你確認願意付這個成本，再顯式開啟。

它不會亂跑

只有在「這次對話真的有歸檔到新素材」時才觸發（沒有新東西就不值得花 token）；而且同一時間只會有一個蒸餾在跑，靠一個 lock 檔防止重複啟動。

去哪看它有沒有跑

背景蒸餾的所有輸出都會寫進這個記錄檔（在書庫資料夾的 .elegent-state/ 下）。想確認有沒有跑、跑得順不順，看它就對了：

tail -f .elegent-state/autodigest.log

看到蒸餾的執行過程與結果，代表它有在動；檔案一直沒長大，代表沒被觸發（可能沒開、或這次沒有新素材）。

怎麼關閉

把剛才設的變數拿掉即可：從 ~/.zshrc 刪掉那行（或改成 ELEGENT_AUTO_DIGEST=0）後開新終端機；GUI app 則執行 launchctl unsetenv ELEGENT_AUTO_DIGEST 再重啟 app。關掉後，隨時還能手動喊「蒸餾」或打 /digest。

7把記憶接到其他 AI 產品

你的書庫附了一個 MCP 記憶伺服器（名為 elegent-memory，用 elgt mcp 啟動）。任何支援 MCP 的 AI 工具掛上它，就能讀你這座書庫——喚醒開場記憶、搜尋、精讀。它只讀不寫，安全無虞。

一個關鍵設定：ELEGENT_VAULT

伺服器預設去「當前工作目錄下的 vault/」找書庫。但別的 app 啟動時的工作目錄通常不是你的記憶資料夾，所以要用環境變數 ELEGENT_VAULT 明確指到你 vault 的絕對路徑。下面每個範例都會帶上它。

在書庫自己的資料夾裡不用設

elgt init 會依 scope 自動註冊 elegent-memory。user scope 寫到工具的使用者設定；project/local scope 則讓該資料夾能讀到自己的 vault。下面這些設定是給額外 app／專案手動掛載用的。

接到 Claude Desktop

  1. 打開 MCP 設定
    Claude Desktop → Settings（設定）→ Developer / MCP，編輯它的設定檔 claude_desktop_config.json。
  2. 在 mcpServers 裡加一個 elegent-memory 條目
    GUI app 讀不到終端機的 PATH，command 請填 elgt 的絕對路徑（用 which elgt 查；ELEGENT_VAULT 也用絕對路徑）：
    // claude_desktop_config.json{ "mcpServers": { "elegent-memory": { "command": "/Users/你/.local/bin/elgt", "args": ["mcp"], "env": { "ELEGENT_VAULT": "/Users/你/my-memory/vault" } } } }
  3. 重啟 Claude Desktop，實測
    重開後，對它說「喚醒你的記憶」或「幫我搜尋書庫裡關於 ○○ 的紀錄」。它應會用 memory_wake / memory_search 讀到你的內容。

接到其他專案的 Claude Code

兩種做法，擇一：

做法怎麼做
用 claude mcp add 或專案 MCP 設定 可用 Claude CLI 將 elegent-memory 加到 user/project/local scope，或在該專案的 MCP 設定加入同樣條目（command: "elgt"、args: ["mcp"]、env.ELEGENT_VAULT 指到你的 vault）。
臨時用 --mcp-config 把設定存成一個檔（如 elegent.mcp.json），啟動時帶上 claude --mcp-config /路徑/elegent.mcp.json。不想改動專案檔時很方便。

接到 Codex CLI

  1. 找到（或新建）設定檔
    Codex CLI 的設定檔在 ~/.codex/config.toml（TOML 格式）。檔案不存在就直接新建一個。
  2. 加一個 mcp_servers.elegent-memory 區塊
    ELEGENT_VAULT 用絕對路徑：
    # ~/.codex/config.toml[mcp_servers.elegent-memory] command = "elgt" args = ["mcp"] env = { ELEGENT_VAULT = "/Users/你/my-memory/vault" }
  3. 重啟 Codex CLI，實測
    重新啟動後對它說「喚醒你的記憶」或「搜尋書庫裡關於 ○○ 的紀錄」，確認它會呼叫 memory_wake / memory_search。

接到 Gemini CLI

  1. 找到（或新建）設定檔
    Gemini CLI 的設定檔在 ~/.gemini/settings.json（JSON 格式）。檔案不存在就直接新建一個。
  2. 在 mcpServers 裡加一個 elegent-memory 條目
    格式與 Claude Desktop 相同，ELEGENT_VAULT 用絕對路徑：
    // ~/.gemini/settings.json{ "mcpServers": { "elegent-memory": { "command": "elgt", "args": ["mcp"], "env": { "ELEGENT_VAULT": "/Users/你/my-memory/vault" } } } }
  3. 重啟 Gemini CLI，實測
    重新啟動後對它說「喚醒你的記憶」或「搜尋書庫裡關於 ○○ 的紀錄」，確認它會呼叫 memory_wake / memory_search。

接到其他相容 MCP 的工具（通用說明）

任何吃「stdio MCP 伺服器」的工具都能掛。通用參數是同一組三件：

欄位值說明
啟動指令elgt終端機類工具通常找得到 PATH 上的 elgt；GUI app 請填 which elgt 查出的絕對路徑。
參數["mcp"]叫 elgt 以 MCP 伺服器模式啟動。
環境變數ELEGENT_VAULT=/絕對路徑/vault指到你的 vault。省略的話伺服器只會找「該工具工作目錄下的 vault」，多半找不到。
開發模式的等價寫法

在原始碼專案裡用 Bun 的人，啟動指令可以寫 command: "bun"、args: ["/絕對路徑/src/presentation/mcp/server.ts"]——跟 elgt mcp 是同一個伺服器，擇一即可。

四個記憶工具：AI 何時用哪個

掛上 elegent-memory 後，AI 手上多了四個工具。你不用直接操作它們——AI 會依對話需要自己挑。認得它們，能幫你看懂 AI 正在做什麼。

開場 · 想起你是誰

memory_wake

對話一開始就用。回傳「喚醒包」——你的身分（identity）＋現在最重要的事（essential-story）。讓 AI 開口前先想起你是誰、正在忙什麼。

找記憶 · 關鍵字搜尋

memory_search

當 AI 需要確認「這件事之前談過嗎」。對整座書庫的筆記逐行搜尋關鍵字，回傳命中的「檔案:行號:片段」，快速定位相關頁面。

精讀 · 讀整篇

memory_read

搜尋定位到某一頁後，用它把整篇讀進來看細節。是「找到了 → 打開來仔細看」的那一步。

導覽 · 瀏覽目錄

memory_list

列出書庫某一層的目錄與檔案，像逛書架。當 AI 想先摸清結構、或不確定該往哪找時用來導覽。

典型的一次記憶取用

開場 memory_wake 想起你 → 遇到具體問題 memory_search 找出相關頁 → memory_read 讀該頁細節（必要時 memory_list 先看看附近還有什麼）。四個工具合起來，就是 AI 在別的產品裡「翻你這座書庫」的方式。

8多座記憶：一個資料夾一座書庫

預設的 user scope 是「到處都自動記錄、到處都能查」的唯一一份全域書庫——hooks 與 MCP 的自動掛接都是機器層級的單一入口（同一個 elegent-memory 名稱）。連續對兩個資料夾都跑預設的 elgt init（皆為 user scope）並不會變成兩座互不干擾的書庫：第二次的 MCP 註冊會被跳過（查詢仍只指向第一座），但 hooks 兩份都會留著，變成所有對話同時寫進兩座 vault。想要真正獨立、只在特定資料夾生效的記憶，請改用 project 或 local scope，而不是重複用 user scope。

比方說：全域個人記憶只需初始化一次（預設 user scope，到處都能記錄／查詢）：

elgt init

某個特定專案想額外疊一份只在該專案生效的記憶，就在該專案資料夾裡另外用 project／local scope：

cd ~/code/my-app && elgt init --claude-scope local --codex-scope local --agy-scope local

在 ~/code/my-app 裡開的 Claude Code，查詢時會同時涵蓋「全域記憶 + my-app 專案記憶」；在別的資料夾則只看得到全域記憶。project scope 建立可見、進版控的 專案名.vault/；local scope 建立隱藏、gitignored 的 .專案名.vault/。

scopevault 位置適合情境
user（預設）vault/ 或你指定的名稱個人主記憶，跨對話與工具共用。
project專案名.vault/想把專案記憶明確放在 repo 旁邊、可見且可選擇納入版本管理。
local.專案名.vault/專案私有記憶，不想進 git；elgt init 會自動加入 .gitignore。

掛到別的 App 時，怎麼指定是哪一座

第 7 章的所有掛接設定裡，ELEGENT_VAULT 指到哪座 vault，掛的就是哪座記憶。想在某個工具裡改看另一份沒有自動掛接的 vault，把 ELEGENT_VAULT 指到那份 vault 的絕對路徑即可。要區分掛的是哪一座記憶，靠的就是這個變數。

情境要不要設 ELEGENT_VAULT為什麼
在書庫自己的資料夾裡開 Claude Code不用init 已設定好，AI 依當前資料夾自動找到 vault/。
把某座記憶掛到別的 App／別的專案要那個 App 的工作目錄不是你的記憶資料夾，得用絕對路徑明確指出是哪一座。
掛到 GUI app 時，command 請用絕對路徑

從 Dock／Finder 圖示點開的 app（如 Claude Desktop）讀不到你終端機的 PATH 設定，只寫 "command": "elgt" 它可能找不到。在終端機跑 which elgt 查出絕對路徑，填進設定檔，例如 "command": "/Users/你/.local/bin/elgt"，改完重啟該 app。

9保養

三個安全網加一個自動雇員，讓圖書館長期保持整齊、且永遠能反悔。以下指令都在書庫資料夾裡執行。

健康檢查

像圖書館盤點。回報 0 errors 代表一切整齊。

elgt lint

它分兩級：硬錯誤（例如檔案格式壞掉、動到只讀檔）會列出來讓 AI 修好；軟提醒（缺描述、連結指向還沒寫的頁、有專案該搬進 archives）只是建議，不急著處理。

補檔

萬一某些對話因為當機或特殊情況漏了歸檔，這個指令會掃描歷史對話、把漏掉的補進書庫。是自動歸檔的安全網。

elgt backfill

目錄自動更新

書庫每個資料夾都有一份 index.md 目錄，它會自己保持最新：每次對話結束、且成功歸檔後，系統會就地重生所有 index.md（純文字重算，很快，不呼叫 AI、不花額度）。想立刻重生（例如剛手動改了某頁的一句話描述），手動指令也在：

elgt reindex
別手改 index.md

index.md 是自動生成的，手改會在下次重生時被蓋掉。要調整顯示內容，改各知識頁自己的 title / description；要調整導覽路線，改 palace/map.md。

git 版本安全網

elgt init 建書庫時就自動建好了 git 版本庫，之後每次蒸餾都會自動存一個「版本存檔點」（git commit）。你不需要懂 git 的細節——只要記得一件事：每一步都有存檔，任何整理都能反悔、退回上一版。這也是為什麼系統敢放心讓 AI 自動寫入。

10疑難排解

按症狀分三組：安裝與升級、歸檔與蒸餾、MCP 連線。

安裝與升級

macOS 說「無法打開，因為無法驗證開發者」

這是 macOS 的 Gatekeeper 安全機制：對「不是從 App Store 或瀏覽器正常管道下載」的執行檔，預設先攔下來。移除那個攔阻標記即可（一行安裝的腳本已自動處理，只有手動下載才需要這步）：

xattr -d com.apple.quarantine ~/.local/bin/elgt

之後再跑 elgt version 就不會被擋了。

打 elgt 卻說 command not found

檔案裝好了，但系統的搜尋清單（PATH）裡沒有它所在的資料夾。把安裝目錄加進 PATH——加到你的 shell 設定檔（zsh 是 ~/.zshrc，bash 是 ~/.bashrc）：

# ~/.zshrc　（或 ~/.bashrc）export PATH="$HOME/.local/bin:$PATH"

存檔後開一個新的終端機視窗讓它生效，再驗證：

which elgt elgt version

which elgt 印得出路徑，就代表系統找得到它了。

怎麼升級到新版

看你當初怎麼裝的，對應著更新：

  • 一行安裝（方式 A）的人：重跑一次同一句 curl ... | bash。它會抓最新 release 覆蓋掉舊的那顆。
  • 自己編（方式 C）的人：在原始碼資料夾重跑 bun run build，再把新的 dist/elgt 覆蓋到 PATH 上那顆（例如重跑 cp dist/elgt ~/.local/bin/elgt）。

升級完打 elgt version，版本號有變就成功了。你的記憶內容（各資料夾的 vault/）完全不受影響——升級換的只是工具本身。

我的電腦不是 macOS（Apple 晶片）

目前現成執行檔只有 macOS arm64 版。在 Intel Mac、Linux、Windows 上，暫時沒有可下載的 elgt——請改用開發模式：裝好 Bun、抓原始碼，用 bun run ... 這一整套指令（見速查的對照表）。功能完全一樣，只是需要先有 Bun。

歸檔與蒸餾

對話好像漏歸檔了，怎麼辦？

跑一次補檔就好，它會把漏掉的對話補進書庫：

elgt backfill

開了自動蒸餾，卻沒反應

最常見的坑：環境變數沒傳進 GUI app。你在終端機 export ELEGENT_AUTO_DIGEST=1，只對「從那個終端機啟動的程式」有效；從 Dock／Finder 點開的 app 看不到。解法見第 6 章情況 B：用 launchctl setenv 設定後重啟 app。

其他要確認的：

  • 這次對話有沒有歸檔到新素材——沒有新東西就不會觸發。
  • claude 指令是否在 PATH 上——背景蒸餾要靠它啟動；同時檢查 .elegent-state/hooks.log（spawn 失敗會記在這裡，例如「找不到 claude 指令」）。
  • 看 .elegent-state/autodigest.log 有沒有輸出；完全沒動，代表根本沒被觸發（多半是變數沒吃到）。

自動蒸餾好像卡住了 / lock 卡住

蒸餾靠 .elegent-state/digest.lock 這個檔防止重複啟動，裡面存的是持有者的程序編號（PID）。系統會自癒：下次要蒸餾時若發現持有者早就結束了，會自動把過期的 lock 清掉再重跑，通常你什麼都不用做。

若真的想手動強制解鎖，先確認持有者程序真的死了再刪，避免誤殺還在跑的蒸餾：

kill -0 $(cat .elegent-state/digest.lock) 2>/dev/null || rm .elegent-state/digest.lock

一次蒸餾的結果不滿意，能反悔嗎？

能。每次蒸餾都是一個 git 存檔點，請 AI（或用 git）退回蒸餾前的版本即可。更關鍵的是——逐字層存證從來不會被動到，原始對話永遠都在，重跑一次蒸餾就好。

MCP 連線

MCP 連不上 / 別的 app 看不到記憶

三個地方最常出錯，逐一檢查：

  • elgt 路徑：GUI app 讀不到你終端機的 PATH，不一定找得到 elgt。用終端機跑 which elgt 查出絕對路徑，把設定裡的 "command": "elgt" 換成該絕對路徑。
  • 工作目錄（cwd）／ELEGENT_VAULT：伺服器預設找「cwd 下的 vault」，但別的 app 的 cwd 多半不是你的記憶資料夾。務必用 ELEGENT_VAULT 指到 vault 的絕對路徑。
  • 路徑寫對了嗎：command 與 ELEGENT_VAULT 都用絕對路徑，別留相對路徑。改完重啟那個 app。

手機上怎麼看？

裝 Obsidian 手機版，搭配 git 同步（例如 Obsidian Git 外掛或雲端同步）把 vault/ 同步到手機。手機端只用來瀏覽，整理與蒸餾留在電腦上做。

小提醒：init vs scaffold

bun run scaffold 是「在既有的開發專案裡鋪出書庫結構」，屬於 repo 內的開發指令。elgt init 則是「在任何空資料夾一鍵長出完整、獨立可用的一座記憶」——這是給一般使用者的入口，兩者用途不同，別搞混。

記住這三條就夠了

① 建記憶就進資料夾打 elgt init；之後對話自動存底、想整理就喊「蒸餾」。② 每一步都有 git 存檔，任何整理隨時能反悔。③ 接別的 AI 就三件事：elgt 絕對路徑 ＋ ["mcp"] ＋ ELEGENT_VAULT。
