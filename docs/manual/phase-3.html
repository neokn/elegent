Phase 3 · 使用說明書

從我的 repo，變成你桌上的一顆工具

前兩個 Phase，這套記憶系統住在開發者的專案裡：得先 clone 原始碼、裝執行環境、記一串指令。Phase 3 把它整個壓成一顆執行檔——一行安裝、一句指令，任何資料夾都能長出自己的記憶。

這篇適合誰

第一次拿到 palace 執行檔、想直接用起來的人。你不需要懂程式、不需要裝任何開發工具。Phase 1／2 講的「這座書庫是什麼、怎麼跟 AI 一起用」在這裡完全不變——這篇只講一件新事：怎麼把它從原始碼變成一顆到處能跑的工具。

1Phase 3 是什麼

同一套記憶系統，換了一種交付方式：從「一份要自己組裝的原始碼」變成「一顆現成的執行檔」。

在 Phase 1 和 2，要用這套系統，你得先把整個開發專案（repo）抓下來、裝好它的執行環境（Bun），再記住一串 bun run 這個、bun run 那個 的指令。那比較像是「拿到一箱零件，自己按圖組一台機器」——對開發者剛好，對一般人門檻偏高。

Phase 3 做的事，是把那一整箱零件——所有程式、所有範本、連同它需要的執行環境——壓縮進單獨一個檔案，取名 palace。你不用再組裝，把這顆檔案放到系統找得到的地方，之後在任何地方打 palace 就能用。

一個比喻

以前是「要用某個工具，得先把整間工具房搬過來」；現在是一支瑞士刀——所有刀刃都收在同一個握把裡，一個檔案，放進口袋（PATH）就走到哪用到哪。這顆檔案約 57 MB，看起來不小，是因為它把「執行環境」也一起打包了，所以你的電腦上什麼都不用先裝。

📦

一顆執行檔

程式、範本、執行環境全包在單一檔案裡。不必安裝 Bun、不必抓原始碼，下載即用。

⬇️

一行安裝

一句 curl 指令，自動下載、放到定位、處理好權限。裝完打 palace version 就能驗證。

🏗️

空資料夾一鍵成形

palace init 能在任何空資料夾裡，一次長出一座完整、可用的記憶書庫。

已經在用開發模式的人：不受影響

如果你本來就照 Phase 1／2 用 bun run ...，那條路原封不動保留。palace 只是多開一條「免裝 Bun」的路，兩邊跑的是同一份邏輯。想知道舊指令怎麼對到新指令，看第 4 節。

2安裝 palace

三種方式，任選一種。裝完都用同一句話驗證：palace version 印出版本號就成功了。

先確認：平台與發佈狀態

目前提供的現成執行檔只支援 macOS（Apple 晶片，arm64）。另外，方式 A／B 都是去 GitHub 的 Releases 抓檔，所以前提是 neokn/llm-wiki 這個專案已經發佈過一版 release（且附了 palace-darwin-arm64 這個檔）。若還沒有 release，或你的電腦不是 macOS arm64——請走方式 C：自己編一顆。

方式 A · 一行安裝（最省事，建議）

打開「終端機」，把下面這行貼上去按 Enter。它會自動下載最新版、放到 ~/.local/bin/palace、順手處理好 macOS 的安全性攔阻：

curl -fsSL https://raw.githubusercontent.com/neokn/llm-wiki/main/install.sh | bash

裝完你會看到「已安裝 …/palace」。如果它提醒你 ~/.local/bin 不在 PATH（系統找不到指令的清單）裡，照它印出的那行 export PATH=... 加進你的設定檔、重開一個終端機視窗即可（詳見第 6 節）。

方式 B · 手動下載（不想用 curl 管線時）

  1. 到 Releases 頁抓檔
    打開 github.com/neokn/llm-wiki/releases，在最新一版下載名為 palace-darwin-arm64 的檔案。或直接用這個「永遠指向最新版」的網址：
    https://github.com/neokn/llm-wiki/releases/latest/download/palace-darwin-arm64
  2. 改名、給執行權限、放進 PATH
    把它改名成 palace、標記為可執行，放到系統找得到的地方（例：~/.local/bin）：
    mkdir -p ~/.local/bin mv ~/Downloads/palace-darwin-arm64 ~/.local/bin/palace chmod +x ~/.local/bin/palace
  3. 解除 macOS 的下載攔阻
    從瀏覽器下載的執行檔，macOS 會先攔下來。手動移除這個標記（方式 A 的安裝腳本已自動做了這步）：
    xattr -d com.apple.quarantine ~/.local/bin/palace

方式 C · 自己編一顆（沒有 release，或非 macOS-arm64）

這條路需要 Bun（開發環境），適合「還沒發佈 release」或「想自己掌握版本」的情況。在專案原始碼資料夾裡：

bun install bun run build

完成後會在 dist/palace 產出一顆執行檔（約 57 MB）。把它複製或連結到你 PATH 上的資料夾即可，例如：

cp dist/palace ~/.local/bin/palace
關於平台

目前 bun run build 只鎖定 macOS arm64 這個目標。其他平台（Intel Mac、Linux、Windows）暫時沒有現成執行檔——在那些系統上，請仍以 Phase 1／2 的開發模式（裝 Bun、用 bun run ...）使用。

驗證安裝

不管用哪種方式，開一個新的終端機視窗，打：

palace version0.3.0

看到版本號（如 0.3.0）印出來，就代表 palace 已就位、系統找得到它。若出現「command not found」，是 PATH 沒設好，見第 6 節。

3快速開始：三句指令建一座記憶

裝好 palace 後，在任何空資料夾裡跑一次 palace init，就能長出一座完整、當場可用的記憶書庫。

  1. 建一個資料夾，走進去
    名字隨你取，這裡叫 my-memory。它會是你這座書庫的家。
    mkdir my-memory && cd my-memory
  2. 一鍵初始化
    這一句會在當前資料夾鋪好整套系統：一個 vault/ 書庫（含 palace/ 記憶宮殿與 PARA 分類）、一份給 Claude Code 的 CLAUDE.md 說明，以及一個已經指向 palace 自己的 .mcp.json。
    palace init
    跑完它會告訴你新增了哪些檔案，並列出「下一步」。
  3. 填自我介紹（identity）
    用任何編輯器打開這個檔，寫下「你是誰、身邊關鍵的人、你希望 AI 怎麼跟你互動」。這是 AI 每次開場「想起你」的依據：
    vault/palace/wake/identity.md
  4. （建議）用 Obsidian 打開 vault 資料夾
    把 my-memory/vault 當成一個 Obsidian vault 打開，就能像逛筆記一樣瀏覽、雙向連結你的記憶。這步純為了你自己看，不影響 AI 使用。
  5. 在這個資料夾裡開 Claude Code——記憶自動生效
    在 my-memory 資料夾裡啟動 Claude Code（若已開著，重啟或開一個新對話）。因為 init 已經把記憶 hooks 與 palace-memory 記憶伺服器都寫進這個資料夾的設定，這裡的每個 session 都會自動掛上你的記憶——開場想起你、對話結束自動歸整。你什麼都不用手動接。
為什麼「這個資料夾」就自動生效

init 產生的 .mcp.json 與 hook 設定，都指向你剛裝好的 palace 執行檔本身。Claude Code 一進到這個資料夾就會讀到這些設定，於是記憶伺服器與 hooks 自動啟用——綁定的是「資料夾」，不是某個全域開關。換到別的資料夾，就是另一座（或沒有）記憶，見第 5 節。

4舊指令怎麼變：bun ↔ palace 對照

前兩個 Phase 的每個 bun run ...，在 Phase 3 都有一個等價的 palace ...。兩邊跑的是同一份邏輯，差別只在「要不要先裝 Bun」。

你想做的事開發模式（需 Bun）執行檔模式
從零建一座記憶（空資料夾）—（新功能）palace init
重生目錄索引 index.mdbun run reindexpalace reindex
檢查書庫格式（lint）bun run lint:vaultpalace lint
回填舊的對話逐字稿bun run backfillpalace backfill
啟動記憶伺服器（MCP）bun tools/mcp/server.tspalace mcp
對話結束等時機的 hooksbun tools/hooks/stop.ts 等palace hook stop 等
檢查檔案是否違反 append-onlybun tools/cli/guard.ts <檔>palace guard <檔>
看版本—palace version
開發模式仍然全都能用

如果你在原始碼專案裡、也裝了 Bun，所有 bun run ... 照舊可用，跟 palace 子指令等價、可混用。palace 是為「不想／不需要碰 Bun 的人」而生的入口，不是取代——你原本的習慣不必改。

小提醒：init vs scaffold

Phase 1 的 bun run scaffold 是「在既有的開發專案裡鋪出書庫結構」，屬於 repo 內的開發指令，仍保留原樣。palace init 則是「在任何空資料夾一鍵長出完整、獨立可用的一座記憶」——這是給一般使用者的新入口，兩者用途不同，別搞混。

5多座記憶：一個資料夾一座書庫

在不同資料夾各跑一次 palace init，就會有各自獨立的記憶系統——各自的書庫、各自的內容、互不干擾。

比方說，你可以這樣分：

mkdir ~/work-memory && cd ~/work-memory && palace init mkdir ~/life-memory && cd ~/life-memory && palace init

現在你有兩座完全獨立的書庫。在 ~/work-memory 裡開的 Claude Code 只看得到工作記憶；在 ~/life-memory 裡開的只看得到生活記憶。因為每座的設定都指向「自己資料夾裡的 vault」，AI 會依你當下所在的資料夾，自動用對應那座——同資料夾情境下，你什麼都不用額外指定。

把某一座記憶掛到別的 App：用 PALACE_VAULT 指定

上面是「在書庫自己的資料夾裡用」的情況。但如果你想把某一座特定的 vault 掛到別的地方——例如 Claude Desktop、或另一個不相干的專案——那個 App 的工作目錄不是你的記憶資料夾，它不知道該讀哪一座。這時用環境變數 PALACE_VAULT，明確指出「就是這一座」的絕對路徑：

// 別的 App 的 MCP 設定（例：Claude Desktop 的設定檔）{ "mcpServers": { "palace-memory": { "command": "palace", "args": ["mcp"], "env": { "PALACE_VAULT": "/Users/你/work-memory/vault" } } } }

把 PALACE_VAULT 換成 ~/life-memory/vault，就是掛另一座。要區分掛的是哪一座記憶，靠的就是這個變數。

情境要不要設 PALACE_VAULT為什麼
在書庫自己的資料夾裡開 Claude Code不用init 已設定好，AI 依當前資料夾自動找到 vault/。
把某座記憶掛到別的 App／別的專案要那個 App 的工作目錄不是你的記憶資料夾，得用絕對路徑明確指出是哪一座。
和 Phase 2 一脈相承

Phase 2 講的「把記憶接到其他 AI 產品（Claude Desktop、Codex、Gemini…）」在 Phase 3 只有一處變得更簡單：啟動指令從「bun 加一長串 server.ts 絕對路徑」換成乾淨的 "command": "palace"、"args": ["mcp"]。PALACE_VAULT 指到哪座 vault 的規則完全一樣。

6疑難排解

macOS 說「無法打開，因為無法驗證開發者」

這是 macOS 的 Gatekeeper 安全機制：對「不是從 App Store 或瀏覽器正常管道下載」的執行檔，預設先攔下來。移除那個攔阻標記即可（方式 A 的安裝腳本已自動處理，只有手動下載才需要這步）：

xattr -d com.apple.quarantine ~/.local/bin/palace

之後再跑 palace version 就不會被擋了。

打 palace 卻說 command not found

檔案裝好了，但系統的搜尋清單（PATH）裡沒有它所在的資料夾。把安裝目錄加進 PATH——加到你的 shell 設定檔（zsh 是 ~/.zshrc，bash 是 ~/.bashrc）：

# ~/.zshrc　（或 ~/.bashrc）export PATH="$HOME/.local/bin:$PATH"

存檔後開一個新的終端機視窗讓它生效，再驗證：

which palace palace version

which palace 印得出路徑，就代表系統找得到它了。

怎麼升級到新版

看你當初怎麼裝的，對應著更新：

  • 一行安裝（方式 A）的人：重跑一次同一句 curl ... | bash。它會抓最新 release 覆蓋掉舊的那顆。
  • 自己編（方式 C）的人：在原始碼資料夾重跑 bun run build，再把新的 dist/palace 覆蓋到 PATH 上那顆（例如重跑 cp dist/palace ~/.local/bin/palace）。

升級完打 palace version，版本號有變就成功了。你的記憶內容（各資料夾的 vault/）完全不受影響——升級換的只是工具本身。

我的電腦不是 macOS（Apple 晶片）

目前現成執行檔只有 macOS arm64 版。在 Intel Mac、Linux、Windows 上，暫時沒有可下載的 palace——請改用 Phase 1／2 的開發模式：裝好 Bun、抓原始碼，用 bun run ... 這一整套指令（見第 4 節對照表的左欄）。功能完全一樣，只是需要先有 Bun。

＋速查

Phase 3 最常用的六件事，一表帶走。

你打什麼會發生什麼
curl -fsSL …/install.sh | bash一行安裝／升級：抓最新 release 的 palace 到 ~/.local/bin，並處理好權限。
palace version印出版本號——驗證裝好、系統找得到它。
palace init在當前（空）資料夾一鍵長出完整記憶書庫。之後在這資料夾開 Claude Code 即自動生效。
PALACE_VAULT=/…/vault把某一座記憶掛到別的 App／專案時，用它指定「是哪一座」。同資料夾使用時不用設。

記住這三條就夠了

① 安裝就一行 curl，驗證就 palace version。② 建記憶就進資料夾打 palace init，該資料夾的 Claude Code 自動生效。③ 掛到別的 App 才需要 PALACE_VAULT；升級就重跑安裝／重編。
