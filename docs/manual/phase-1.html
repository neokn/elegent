1這是什麼

把這套系統想像成一座圖書館，裡面有兩種訪客。

給人

📖 閱覽室：PARA

你走進來看整理好的成果。四個資料夾按「你現在能對它做什麼」分類：projects（進行中的專案）、areas（長期責任）、resources（知識主題）、archives（已完結）。

給 AI

🗄️ 書庫：palace 記憶宮殿

人平常不進去，但館員（你的 AI 助理）靠它跨對話記得事情。裡面存放逐字紀錄、事實表、索引——是 AI 的長期記憶基礎設施。

它解決什麼問題？

一般的 AI 每開一次新對話都「從零開始」，像每次都要重新翻一整櫃資料才能回答你，講過的事轉頭就忘——知識不會累積。

這套系統換個做法：AI 把學到的東西寫進一份持久的 wiki，一次寫好、持續維護、越用越聰明。就像把零散便條整理成一本會長大的百科——知識會複利累積。

兩層保存，各司其職

逐字層像錄音存證：對話一字不改地留底，只增不減。蒸餾層是館員讀完存證後、寫成的整潔條目。存證永遠在，所以整理錯了隨時能重來。

2快速開始

五個步驟，第一次設定約 10 分鐘。之後日常幾乎不用碰指令。

  1. 安裝 Bun（系統的執行環境）
    到 bun.sh 依指示安裝，或在終端機執行下面這行。只需做一次。
    curl -fsSL https://bun.sh/install | bash
  2. 安裝相依套件
    在專案資料夾裡執行，把系統需要的零件裝好。
    bun install
  3. 建立圖書館骨架
    一鍵蓋好四個閱覽室資料夾與 palace 書庫。畫面會顯示「建立 N 個檔案」。
    bun run scaffold
  4. 用 Obsidian 打開 vault/
    下載免費的 Obsidian，選「Open folder as vault」，指向 llm-wiki/vault 資料夾。這是你日常瀏覽記憶的視窗。
  5. 填寫 identity.md
    打開 palace/wake/identity.md，寫下「你是誰、生活中關鍵的人、你希望 AI 怎麼跟你互動」。這是唯一需要你親手寫的檔案，AI 只讀不改——它會在每次新對話開場自動想起這些內容。
完成了嗎？

做完這五步，系統就上線了。從現在起，你在這個專案裡跟 AI 的每一段對話都會被自動存進書庫——你什麼都不用做。

3日常使用

兩件事：對話自動存底（你不用管）、想整理時喊一聲蒸餾。

對話自動歸檔（三個時機）

你不需要按任何「儲存」。系統會在三個時機自動把逐字紀錄存進 vault/palace/raw/conversations/<專案名>/：

時機什麼時候為什麼
平時每講約 15 則訊息，背景默默存一次邊聊邊備份，完全不打擾你
壓縮前對話太長、AI 要壓縮記憶之前先完整存檔避免舊內容被壓縮掉、從此消失
結束時關掉對話時再補存一次連很短的對話也不會漏掉

什麼時候跑 /digest（蒸餾）？

逐字紀錄只是「存證」，還沒整理成正式條目。當你想把累積的紀錄整理進 wiki 時，跟 AI 說「消化」「蒸餾」或直接打 /digest。館員會讀還沒整理的紀錄，寫進對應的 PARA 頁面與書庫結構，並自動存檔（git commit）。

建議節奏

一個段落的工作告一段落、或累積了幾則對話後，跑一次蒸餾即可。不必每次對話都跑——存證一直都在，慢慢消化也不會遺失。

在 Obsidian 裡看什麼

看這裡你會看到
PARA 資料夾projects / areas / resources 裡是整理好的知識頁，隨手可讀。
Graph view（關係圖）知識點之間互相連結成一張網，一眼看出主題如何串連。
essential-story.md「現在什麼最重要」的濃縮清單，由蒸餾流程從你的活躍專案自動編出。

5保養

三個安全網，讓圖書館長期保持整齊、且永遠能反悔。

健康檢查

像圖書館盤點。回報 0 errors 代表一切整齊。

bun run lint:vault

它分兩級：硬錯誤（例如檔案格式壞掉、動到只讀檔）會列出來讓 AI 修好；軟提醒（缺描述、連結指向還沒寫的頁、有專案該搬進 archives）只是建議，不急著處理。

補檔

萬一某些對話因為當機或特殊情況漏了歸檔，這個指令會掃描歷史對話、把漏掉的補進書庫。是自動歸檔的安全網。

bun run backfill

git 版本安全網

每次蒸餾都會自動存一個「版本存檔點」（git commit）。你不需要懂 git 的細節——只要記得一件事：每一步都有存檔，任何整理都能反悔、退回上一版。這也是為什麼系統敢放心讓 AI 自動寫入。

6常見問題

對話好像漏歸檔了，怎麼辦？

跑一次補檔就好，它會把漏掉的對話補進書庫：

bun run backfill

我想改 index.md，可以嗎？

不要直接改。index.md 是自動生成的目錄，手改會在下次重生時被覆蓋。想調整內容：改各知識頁自己的一句話描述，再跑 bun run reindex 讓目錄重生；想調整導覽路線，改 palace/map.md。

手機上怎麼看？

裝 Obsidian 手機版，搭配 git 同步（例如 Obsidian Git 外掛或雲端同步）把 vault/ 同步到手機。手機端只用來瀏覽，整理與蒸餾留在電腦上做。

一次蒸餾的結果不滿意，能反悔嗎？

能。每次蒸餾都是一個 git 存檔點，請 AI（或用 git）退回蒸餾前的版本即可。更關鍵的是——逐字層存證從來不會被動到，原始對話永遠都在，重跑一次蒸餾就好。

＋指令速查

日常你只會用到少數幾個。打什麼 → 會發生什麼。

你打什麼會發生什麼多久用一次
bun install安裝系統零件只在第一次
bun run scaffold建立圖書館骨架只在第一次
/digest（對 AI 說「蒸餾」）把存證整理進 wiki 並自動存檔累積對話後
bun run lint:vault健康檢查，回報整不整齊偶爾／整理後
bun run backfill把漏歸檔的對話補回來需要時
bun run reindex重生目錄 index.md很少，通常蒸餾會自動做
記住這三條就夠了

① 對話會自動存底，你不用管。② 想整理就喊「蒸餾」。③ 每一步都有存檔，隨時能反悔。
